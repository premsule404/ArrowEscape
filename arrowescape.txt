# Arrow Escape - Phase 3: Game Engine Implementation Plan

## Goal Description
Implement the core puzzle game engine in pure Python. This engine will contain zero UI code, ensuring it is 100% portable across the FastAPI backend, the Web frontend (via Pyodide), and the Android App (Kivy). 

## User Review Required
> [!IMPORTANT]
> Please review the proposed class structure and logic flow. Once approved, I will implement these modules in the `shared/engine` directory and write unit tests to verify their behavior.

## Proposed Architecture

We will create the following Python modules inside `/shared/engine`:

### 1. `models.py`
Defines the primitive data structures using Python `dataclasses` and `enums`.
- `Direction(Enum)`: `UP`, `DOWN`, `LEFT`, `RIGHT`.
- `Position(NamedTuple)`: `x: int`, `y: int`.
- `Arrow(dataclass)`: 
  - `id: str`
  - `position: Position`
  - `direction: Direction`
  - `color_theme: str` (optional aesthetic data)

### 2. `board.py`
Manages the mathematical grid and spatial lookups.
- `Board`:
  - `width: int`, `height: int`
  - `arrows: dict[str, Arrow]`
  - `grid: list[list[Optional[str]]]` (2D array mapping positions to Arrow IDs)
  - **Methods**: `add_arrow()`, `remove_arrow()`, `get_arrow_at()`, `is_out_of_bounds()`.

### 3. `events.py`
A simple callback/hook system so the UI (Canvas/Kivy) can subscribe to engine events for animations and sounds.
- `EventDispatcher`:
  - Hooks: `on_arrow_slide(arrow)`, `on_arrow_blocked(arrow)`, `on_win()`.

### 4. `engine.py`
The primary controller that mutates the state.
- `GameEngine`:
  - **State**: Current `Board`, `move_history` (stack for Undo).
  - **Methods**:
    - `load_level(level_dict: dict)`
    - `can_move(arrow: Arrow) -> bool`: Checks if the path to the edge of the board in `arrow.direction` is free of other arrows.
    - `tap_arrow(arrow_id: str) -> bool`: Attempts to move an arrow. Triggers events. If successful, adds to `move_history` and removes the arrow from the board.
    - `undo() -> bool`: Pops the last move and restores the arrow to the board.
    - `restart()`: Restores the board to the initial level state.
    - `is_level_complete() -> bool`: Checks if the board is empty.

### 5. `solver.py` (Hint System)
Provides algorithmic puzzle solving to generate hints.
- `HintSystem`:
  - Uses **Depth-First Search (DFS)** or **Breadth-First Search (BFS)** with memoization (tracking visited board states) to find a valid sequence of arrow taps that clears the board.
  - **Method**: `get_next_hint(board_state) -> Arrow`

## Verification Plan

### Automated Tests
I will create a suite of `pytest` unit tests in `/tests/test_engine` to verify:
1. `test_movement_validation`: Arrows correctly identify if they are blocked or free.
2. `test_state_mutation`: Tapping a valid arrow successfully removes it and updates the grid.
3. `test_undo_restart`: Undo stack accurately restores the previous board state.
4. `test_win_condition`: Engine correctly identifies an empty board as a win.
5. `test_solver`: The solver can successfully find the solution to a simple 3x3 puzzle.

## Open Questions
> [!TIP]
> Are you okay with utilizing Python `dataclasses` and strict typing for the engine? (This is standard best practice and will help prevent bugs when we integrate it with the UI later).

# Arrow Escape - Phase 5: Web Frontend Implementation Plan

## Goal Description
Develop a responsive, professional HTML5/Canvas web application for Arrow Escape. Crucially, we will integrate **Pyodide** to run our pure Python game engine (`shared/engine`) directly in the browser. This guarantees zero duplication of game logic while providing an offline, real-time 60FPS web experience.

## User Review Required
> [!IMPORTANT]
> Please review the proposed architecture for the Web Frontend. Once approved, I will build out the `index.html`, `styles.css`, and `app.js`, and connect it to our Python engine!

## Proposed Architecture (`frontend/`)

### 1. Structure
- `frontend/public/index.html`: The single-page app layout, containing the Canvas element, top/bottom navigation UI, modals (Pause, Victory), and importing the Pyodide CDN.
- `frontend/src/styles.css`: Vanilla CSS utilizing dark mode, flexbox/grid for responsiveness, and beautiful micro-animations for UI buttons.
- `frontend/src/app.js`: The main JavaScript controller.

### 2. Pyodide Integration (`app.js`)
When the page loads, `app.js` will:
1. Download and initialize the Pyodide WebAssembly runtime.
2. Fetch our Python files (`engine.py`, `models.py`, `board.py`, `level_parser.py`) and mount them into Pyodide's virtual filesystem.
3. Fetch a level JSON (e.g., `level001.json`).
4. Execute Python code via JS to instantiate the `GameEngine` and load the level!

### 3. Canvas Rendering (View)
- `app.js` will feature a `Renderer` class.
- It calculates the tile size based on screen dimensions to be 100% responsive.
- Draws a subtle grid background.
- Draws arrows as colorful rounded rectangles with directional icons (↑ ↓ ← →).
- Implements an interpolation loop (`requestAnimationFrame`) to handle the smooth slide-out and shake animations when Python events fire.

### 4. Input & Control (Controller)
- Adds `pointerdown` listeners to the Canvas to support both mouse clicks and touch taps.
- Calculates which grid cell was tapped.
- Calls the Python `engine.tap_arrow(id)` function.
- If Python returns `True`, triggers slide-out. If `False`, triggers the error shake.

- Verify the canvas scales correctly on desktop and mobile views.
- Verify tapping an arrow correctly executes the Python logic and slides the arrow.

# Arrow Escape - Phase 7: Database Architecture Implementation Plan

## Proposed Architecture (`backend/app/models/`)

We will create the following tables spread across domain-specific modules:

### 1. Core & Auth (`user.py`)
- **`users` table**:
  - `id` (Primary Key)
  - `username` (String, Unique)
  - `email` (String, Unique, Nullable)
  - `hashed_password` (String)
  - `is_guest` (Boolean)
  - `created_at` (DateTime)

### 2. Game Progress (`game.py`)
- **`levels` table**:
  - `id` (String, Primary Key - e.g., "level001")
  - `name` (String)
  - `difficulty` (Integer)

  - `id` (Integer)

  - `level_id` (Foreign Key -> `levels.id`)

  - `best_moves` (Integer)

- **`achievements` table**:
  - `id` (String, Primary Key)
  - `name` (String)
  - `description` (String)
  - `reward_coins` (Integer)
- **`user_achievements` table**:
  - Maps `user_id` to `achievement_id` with an `unlocked_at` timestamp.

- **`profiles` table**: (1-to-1 with `users`)

  - `current_theme` (String)
- **`themes` table**:
  - `id` (String, Primary Key)
  - `name` (String)
  - `cost` (Integer)
- **`purchases` table**:
  - Maps `user_id` to `theme_id` representing ownership.

### 4. Meta & Settings (`stats.py`)
- **`settings` table**: (1-to-1 with `users`)
  - `user_id` (Primary Key)
  - `sound_enabled` (Boolean)
  - `dark_mode` (Boolean)

  - `user_id` (Primary Key)
  - `total_arrows_cleared` (Integer)

## 🔍 Root Cause of Replay Timer Bug

When a level was completed, `on_win` in `android/ui/game_screen.py` cancelled Kivy's timer event (`self.timer_event.cancel(); self.timer_event = None`). When `↻ REPLAY LEVEL` / `on_restart` was triggered, `self.engine.restart()` reset engine parameters, but **`self.timer_event` was never re-scheduled**!
As a result, `Clock.schedule_interval(self.on_timer_tick, 0.1)` was missing on replay, causing the countdown timer to stay frozen.

3. Restarting during gameplay (`↻ RESTART` in Pause Menu / Footer)
4. Retrying after failure (`↻ RESTART` in Game Over)

- Unschedules/cancels any existing Kivy `timer_event`.
- Dismisses any active popups.

# Multi-Platform Online Architecture & Implementation Roadmap: Arrow Escape

A comprehensive architectural blueprint and multi-phase implementation roadmap to transform **Arrow Escape** into a public, cross-platform online game with cloud save, unified player accounts, REST APIs, and multi-platform deployment (Web, Android, Desktop).

---

## 🏛️ 1. Architecture Review & Module Classification

### A. Immutable Core Modules (100% Preserved)
The shared Python game engine remains the single source of truth:
- **Game Engine & Rules**: `shared/engine/` (`engine.py`, `board.py`, `models.py`, `solver.py`, `constants.py`, `events.py`).
- **Level Definitions**: `levels/level001.json` through `level050.json` (Grid sizes, arrow placement, Color Confusion Mode, Black Master Arrow markers).
- **Core Mechanics**: 3 Hearts/Lives system, Timer ($1\text{s/arrow}$), Star thresholds ($50\%, 70\%, 80\%$), Coin rewards ($100\%, 70\%, 50\%$), Anti-farming incremental rewards, Replay, Pause/Resume, Undo, and Hint System.

### B. Modules To Be Expanded / Transformed
- **Backend (`backend/`)**: FastAPI REST API v1 endpoints for Auth, Players, Cloud Save, Sync, Leaderboards, Stats, Achievements, Admin Dashboard.
- **Database (`database/` & `backend/app/models/`)**: Production PostgreSQL schema with SQLAlchemy ORM models and Alembic migrations.
- **Frontend (`frontend/`)**: Modern responsive web application (HTML5 Canvas + CSS/JS UI) supporting Web Browser, Capacitor (Android APK/AAB), and Electron (Desktop Windows/Mac/Linux).
- **Authentication**: JWT + Refresh tokens, Guest, Email/Password, Google OAuth, Apple OAuth ready.
